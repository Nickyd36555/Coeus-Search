Facebook Marketplace car monitor

Getting fbmarket running

From an empty terminal to your phone buzzing when a car you actually want hits Marketplace. Eleven steps, four checkpoints, about twenty minutes.

Time ~20 min You need a computer that stays on Alerts go to Discord

Install it

Steps 1–4
1

Check you have Python 3.10 or newer

Open a terminal (on Windows, use PowerShell) and run:

$ python3 --version

If it prints 3.10 or higher, skip ahead. Otherwise install it:

macOS
$ brew install python
# no Homebrew? download from python.org/downloads
Windows
# Download from python.org/downloads and run the installer.
# Tick "Add python.exe to PATH" on the first screen — easy to miss,
# and nothing below works without it.
Linux / Raspberry Pi
$ sudo apt update
$ sudo apt install python3 python3-venv python3-pip git
2

Download the code

$ git clone https://github.com/Nickyd36555/Coeus-Search.git
$ cd Coeus-Search

Every command from here on runs inside that folder.

3

Create an isolated environment and install

The virtual environment keeps this project's packages away from the rest of your system, so nothing here can break anything else.

macOS / Linux
$ python3 -m venv .venv
$ source .venv/bin/activate
$ pip install -e ".[web]"
Windows PowerShell
> python -m venv .venv
> .venv\Scripts\Activate.ps1
> pip install -e ".[web]"
Checkpoint

Your prompt should now start with (.venv). Confirm the tool is installed: 

$ fbmarket --version
fbmarket 1.0.0

If your terminal says fbmarket: command not found, the environment isn't active — re-run the activate line above. You need it in every new terminal window.

4

Install the browser it drives

Marketplace only renders its listings for a real browser, so the tool drives a headless Chromium. This downloads it (~150 MB, once). 

$ playwright install chromium

On Linux or a Raspberry Pi, also install the system libraries it needs:

$ sudo playwright install-deps chromium

Connect your alerts

Steps 5–6
5

Create a fresh Discord webhook

Do this one properly

The webhook you sent me is in our chat transcript, which means it should be considered compromised — anyone holding that URL can post into your channel. Make a new one and don't paste it into a chat again.

In Discord: Server Settings → Integrations → Webhooks → New Webhook. Pick the channel you want car alerts in, then Copy Webhook URL.

Now create a file called .env in the project folder:

# .env
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/PASTE_YOURS_HERE

That file is already git-ignored, so the secret can't get pushed to GitHub by accident. The tool loads it automatically.

6

Switch Discord on and prove it works

Copy the example config:

$ cp config.example.yaml config.yaml

Open config.yaml in any text editor. Find the discord block and change enabled: false to enabled: true: 

    - type: discord
      enabled: true
      webhook_url: ${DISCORD_WEBHOOK_URL}

Then check the config is valid and fire a test alert:

$ fbmarket check
$ fbmarket test-notify
Checkpoint

A fake Tacoma listing should appear in your Discord channel within a couple of seconds. Don't move on until it does — every later step assumes alerts reach you.

Tell it what to hunt

Steps 7–9
7

Open the interface

$ fbmarket web

Go to http://127.0.0.1:8765 in your browser. The example config ships with three placeholder searches pointed at Salt Lake City — delete or edit them once yours is set up.

Click + New search and fill in the car, your price range, year range and mileage limit.

The one field that trips people up

Location. Open Facebook Marketplace in another tab and look at the address bar. Copy the part straight after /marketplace/ — it'll be either a city name like manchester or a long number like 109470862423276. That exact value goes in the Location box.

Fill in Reject if the listing mentions… generously — salvage, rebuilt, parts only, no title, wanted, lease. This is what stops junk alerts. Then Save search.

8

Test the search and tune it

Press Test next to your new search. It checks Marketplace live and shows every car on the page with a verdict on each — either would alert you, or the exact rule that rejected it, like skipped — price 26,900 > 25,000.

Adjust and re-test until the right cars pass. This is the whole point of the Test button: no guessing why you're getting junk or nothing at all.

If you get zero listings

Facebook may have shown a login wall. Stop the server (Ctrl+C) and run fbmarket login — a browser opens, you log in normally, press Enter, and the session is saved to your own machine. Then start over at step 7.

9

Take a baseline

Press Check once now on the dashboard (or run fbmarket once in a second terminal).

This first pass deliberately stays silent. It records every car already listed so you don't get eighty notifications at once — from here on you'll only hear about cars posted after this moment.

Keep it watching

Steps 10–11
10

Start monitoring

Hit Start monitoring on the dashboard. It now checks every ten minutes and posts anything new to Discord.

Or run it straight from the terminal without the UI:

$ fbmarket watch
Checkpoint

The dashboard should show a green running pill, and the Recently found panel fills up as cars appear. First real alert usually lands within an hour or two, depending on how fast your market moves.

11

Make it survive a reboot

It only alerts while it's running. Closing the terminal stops it. To leave it running permanently:

Linux / Raspberry Pi
# edit the CHANGE_ME paths inside the file first
$ sudo cp deploy/fbmarket.service /etc/systemd/system/
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now fbmarket
$ journalctl -u fbmarket -f   # watch it work
macOS
# replace CHANGE_ME with your username inside the file first
$ cp deploy/com.fbmarket.monitor.plist ~/Library/LaunchAgents/
$ launchctl load ~/Library/LaunchAgents/com.fbmarket.monitor.plist
$ tail -f /tmp/fbmarket.log
Windows
# simplest: leave `fbmarket watch` running in a PowerShell window.
# or use Task Scheduler -> Create Task -> "run whether user is
# logged on or not", pointing at .venv\Scripts\fbmarket.exe watch
Where to run it

Use a machine on your home internet — a spare laptop, a mini PC, or a Raspberry Pi. Facebook is far more suspicious of traffic from datacenter IPs, so a home connection is the single biggest thing keeping this working. That's why a cloud server is the wrong home for it.

When something goes wrong

Reference
The test alert never arrived in Discord

Run fbmarket check — the last line lists which channels are on. If it says NONE, the enabled: true edit in step 6 didn't save.

If it says discord but nothing arrives, the webhook URL in .env is wrong or the webhook was deleted. Recreate it in Discord and paste the new one.

“No listings were found on the page at all”

Usually a login wall. Run fbmarket login and retry.

If that doesn't fix it, capture what Facebook actually sent back. Add to config.yaml under browser::

browser:
  debug_dump_dir: ./debug
  headless: false

Run fbmarket once -v, then inspect the saved page: fbmarket parse debug/<file>.html. With headless: false you'll also see the browser window and can watch exactly where it gets stuck.

Listings are found, but nothing passes my filters

Press Test and read the reason on each rejected car — it names the exact rule. Most common cause is a mileage or year limit catching cars whose title doesn't state a year.

I'm getting alerts about junk — salvage, parts, wanted ads

Add those words to Reject if the listing mentions… in the search form. It matches the title, subtitles and location, and is case-insensitive.

I want to be re-alerted about cars it already found

Press Reset next to the search. That clears its memory, so the next check treats everything as new.

Facebook started blocking or challenging me

Slow it down. In config.yaml raise poll.interval_seconds to 1800 (every 30 minutes). For cars that's still far faster than any human refreshing, and it's much less likely to draw attention.

Commands are the same on every platform once the environment is active. Re-run source .venv/bin/activate in each new terminal.
